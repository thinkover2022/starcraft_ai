이 문서는 원본 개발계획서를 검토해 **무엇을, 어떤 순서로, 어떻게 구현할지**를 다시 쓴 것입니다.

1. 축약어를 쓰지 않습니다. 처음 나올 때 풀어 쓰고, 이후에도 한국어 설명 이름을 씁니다.

## 0. 전체 구성 한눈에 보기

최종 시스템은 같은 윈도우 컴퓨터에서 동시에 실행되는 세 개의 프로그램으로 이루어집니다.

| 프로그램 | 원본 문서의 이름 | 하는 일 |
|---|---|---|
| 화면 인식 프로그램 | P1 | 게임 화면을 초당 24–30장 캡처해 유닛·건물·자원·미니맵·카메라 위치를 읽어 "현재 게임 상태" 데이터로 만든다 |
| 핵심 두뇌 프로그램 | P2 | "현재 게임 상태"를 보고 다음에 할 행동(유닛 선택, 이동, 공격, 생산, 건설 등)을 결정한다 |
| 입력 제어 프로그램 | P3 | 결정된 행동을 실제 키보드·마우스 입력으로 바꿔 게임에 보내고, 제대로 실행됐는지 다음 화면으로 확인한다 |

세 프로그램은 운영체제의 **공유 메모리**(여러 프로그램이 같이 읽고 쓰는 메모리 영역) 두 곳으로만 데이터를 주고받습니다.

- 화면 인식 프로그램 → 핵심 두뇌 프로그램: "현재 게임 상태"
- 핵심 두뇌 프로그램 → 입력 제어 프로그램: "실행할 행동 목록" (반대 방향으로 "실행 결과"가 돌아옴)

### 개발 단계 순서 (개정)

| 단계 | 내용 | 기간(1–2인) |
|---|---|---|
| **1단계** | **객체 인식 모델: 학습 데이터 자동 생성 → 학습 → 평가** | 8–10주 |
| 2단계 | 화면의 나머지 정보 인식: 자원 숫자, 미니맵, 카메라 위치, 정보 패널 | 4주 |
| 3단계 | 추적과 "현재 게임 상태" 조립, 공유 메모리 게시 | 3주 |
| 4단계 | 입력 제어 프로그램 | 3–4주 |
| 5단계 | 규칙 기반 두뇌로 세 프로그램 통합 시험 | 3주 |
| 6단계 | 리플레이 행동 복제 학습 | 8주 |
| 7단계 | 강화학습 미세조정 | 10주 |
| 8단계 | 시뮬레이션과 실제 화면 차이 보정 | 6주 |

원본 문서는 입력 제어 프로그램(원본 M1)을 먼저 만들었지만, 이 개정판은 **객체 인식을 맨 앞에** 둡니다.
입력 제어 프로그램은 1단계와 병행할 수 있는 독립 작업이라 인력이 둘이면 동시에 진행합니다.

## 1단계. 객체 인식 모델 (가장 먼저, 가장 상세히)

### 1.1 목표

게임 화면 한 장을 넣으면, 화면 안의 모든 유닛·건물·자원에 대해 다음을 출력하는 모델을 만듭니다.

- 종류 (예: 건설로봇, 해병, 사령부, 보급고)
- 위치를 감싸는 사각형 (바운딩 박스)
- 객체의 실제 모양 영역 (마스크: 객체에 해당하는 픽셀만 1인 이미지)
- 소유자 (아군 / 적군 / 중립) — 마스크 안의 팀 색상 픽셀로 따로 판정

**완료 기준 (테란 동족전, 1차)**

| 항목 | 목표 |
|---|---|
| 박스 기준 평균 정밀도 평균(IoU 0.5 기준) | 주요 클래스 0.90 이상 |
| 마스크 기준 평균 정밀도 평균(IoU 0.5 기준) | 0.85 이상 |
| 작은 유닛(건설로봇·해병) 재현율 | 0.90 이상 (밀집하지 않은 상황) |
| 소유자 판정 정확도 | 99% 이상 |
| 추론 시간 | RTX 3090에서 화면 1장당 12밀리초 이하 (16비트 부동소수점 최적화 엔진) |

(용어: "평균 정밀도 평균"은 객체 검출 평가의 표준 지표인 mean Average Precision입니다.
"IoU 0.5 기준"은 예측과 정답의 겹친 면적 ÷ 합친 면적이 0.5 이상이면 맞힌 것으로 본다는 뜻입니다.)

### 1.2 범위를 좁혀서 시작: 테란 41개 클래스

처음부터 세 종족 약 230종을 하지 않고 **테란 대 테란 경기만** 대상으로 합니다.
파이프라인이 완성되면 저그·프로토스는 같은 프로그램으로 데이터만 더 만들면 됩니다.

| 분류 | 클래스 |
|---|---|
| 유닛 (15) | 건설로봇(SCV), 해병(Marine), 화염방사병(Firebat), 의무관(Medic), 유령(Ghost), 벌처(Vulture), 거미 지뢰(Spider Mine), 공성 전차-전차 모드, 공성 전차-공성 모드, 골리앗(Goliath), 레이스(Wraith), 수송선(Dropship), 과학선(Science Vessel), 전투순양함(Battlecruiser), 발키리(Valkyrie) |
| 건물 (18) | 사령부(Command Center), 통신 위성 중계소(Comsat Station), 핵 격납고(Nuclear Silo), 보급고(Supply Depot), 정제소(Refinery), 병영(Barracks), 기술 연구소(Engineering Bay), 미사일 포탑(Missile Turret), 사관학교(Academy), 벙커(Bunker), 군수공장(Factory), 기계공장(Machine Shop), 우주공항(Starport), 관제탑(Control Tower), 과학 시설(Science Facility), 비밀 작전실(Covert Ops), 물리학 연구소(Physics Lab), 무기고(Armory) |
| 떠 있는 건물 (6) | 사령부·병영·군수공장·우주공항·과학 시설·기술 연구소가 공중에 뜬 상태 — 모양이 완전히 달라서 별도 클래스로 둠 |

### 1.3 학습 데이터를 만드는 원리

사람이 수십만 장에 손으로 테두리를 그리는 것은 불가능하므로, **리플레이를 재생하면서 정답을 자동으로 만듭니다.**

핵심 아이디어는 정답의 두 부분을 서로 다른 곳에서 얻는 것입니다.

| 정답 정보 | 어디서 얻나 | 이유 |
|---|---|---|
| **무엇인지** (종류, 소유자, 대략 위치) | 게임 정보 인터페이스 라이브러리(BWAPI)가 게임 내부에서 직접 알려줌 | 100% 정확함 |
| **어떤 모양인지** (픽셀 단위 테두리, 마스크) | 범용 영상 분할 모델(Segment Anything Model, 이하 "범용 분할 모델")에 대략 위치를 사각형으로 알려주고 테두리를 따게 함 | 게임 내부 정보는 "충돌 판정용 사각형"만 알려줄 뿐, 화면에 그려진 실제 그림의 범위는 모름 |

**왜 범용 분할 모델이 필요한가:**
게임 정보 인터페이스 라이브러리가 주는 유닛 크기(`getLeft/Top/Right/Bottom`)는 **충돌 판정용 크기**이지 그림 크기가 아닙니다.
예를 들어 건물 그림은 충돌 사각형보다 위로 훨씬 높게 그려지고, 전차 포신은 사각형 밖으로 튀어나옵니다.
이 사각형을 그대로 정답 박스로 쓰면 박스가 실제 그림과 어긋나서 모델이 잘못 배웁니다.
그래서 이 사각형을 "대략 이 근처에 있다"는 힌트로만 주고, 실제 테두리는 범용 분할 모델이 화면 픽셀을 보고 따게 합니다.
**최종 박스는 마스크에서 다시 계산**합니다.

범용 분할 모델은 "무엇인지"는 모르고 "어디까지가 한 덩어리인지"만 압니다.
종류는 게임 내부 정보에서 가져오므로 두 가지를 합치면 완전한 정답이 됩니다.

### 1.4 데이터 생성 프로그램 구성

데이터 생성은 네 개의 프로그램으로 나눕니다. 무거운 분할 모델 계산을 캡처와 분리해야 캡처가 빨라지기 때문입니다.

```
[가] 라벨 수집 확장 모듈 (윈도우, 게임 안에서 실행, C++)
      │  프레임 번호·카메라 위치·화면 안 유닛 목록을 기록하고, 캡처가 끝날 때까지 게임을 멈춤
      ▼
[나] 화면 캡처 프로그램 (윈도우, Python)
      │  같은 프레임의 화면을 무손실 PNG로 저장
      ▼  (원본 화면 PNG + 유닛 목록 JSON 파일 묶음)
[다] 마스크 생성 프로그램 (윈도우, 그래픽 카드, Python + PyTorch)
      │  범용 분할 모델로 유닛별 마스크 생성 → 겹침 정리 → 품질 검사 → 다각형으로 변환
      ▼
[라] 데이터셋 구성 프로그램 (Python)
         리플레이 단위로 학습/검증/시험 분할, 객체 인식 모델 학습 형식으로 저장
```

#### [가] 라벨 수집 확장 모듈

- **실행 환경:** 윈도우 10/11, 스타크래프트 1.16.1, 게임 정보 인터페이스 라이브러리 4.4.0.
  이 라이브러리는 게임 프로세스 안에 32비트 동적 연결 라이브러리(DLL, Dynamic Link Library) 형태로 들어가서 게임 내부 상태를 읽습니다.
  "Chaoslauncher" 같은 실행기로 게임과 함께 띄웁니다.
- **리플레이 모드에서 실행:** 이 라이브러리는 리플레이 재생 중에도 매 프레임 모든 유닛 정보를 제공합니다.
- **매 N프레임(기본 12프레임 = 약 0.5초)마다 하는 일:**
  1. 카메라를 옮깁니다(`setScreenPosition`). 위치는 아래 비율로 고릅니다.
     - 40%: 교전 지점 (양측 유닛이 가까이 모인 곳)
     - 30%: 기지 (사령부 주변, 건물이 많은 곳)
     - 30%: 무작위 위치
  2. 카메라를 옮긴 뒤 **2프레임을 기다립니다**(화면이 새 위치로 다시 그려지도록).
  3. 현재 카메라 위치(`getScreenPosition`)와 화면 안 유닛 목록을 JSON으로 기록합니다.
     유닛마다 종류, 고유 번호, 소유자, 소유자 색상, 맵 좌표, 충돌 사각형, 체력, 선택 여부, 공중 여부, 떠 있는지, 건설 중인지, 은폐 여부를 남깁니다.
  4. 화면 캡처 프로그램에 "캡처하라" 신호를 보냅니다. 윈도우 이벤트 객체와 공유 메모리를 쓰고, 캡처 완료 신호가 올 때까지 이 함수 안에서 기다립니다.
     이 함수가 끝나지 않으면 게임이 다음 프레임으로 넘어가지 않으므로 **화면이 정지된 상태에서 캡처**됩니다.
- **화면 그리기는 켜 둡니다.** 화면 그리기를 끄는 설정(`setGUI(false)`)은 쓰면 안 됩니다. 또 라이브러리 자체의 디버그 그리기(글자, 원)를 하나도 하지 않아야 캡처 화면이 오염되지 않습니다.
- **리플레이 시야:** 리플레이 재생 화면에서 "누구 시야로 볼지"를 무작위로 바꿔서, 전장의 안개가 있는 화면과 없는 화면을 모두 확보합니다.

```cpp
// 라벨 수집 확장 모듈 핵심 (개념 코드)
void LabelCollector::onFrame() {
  int f = Broodwar->getFrameCount();
  if (f % 12 == 0) { Broodwar->setScreenPosition(pickCameraTarget()); pendingFrame = f + 2; }
  if (f != pendingFrame) return;

  json frame;
  frame["frame"] = f;
  frame["camera"] = { Broodwar->getScreenPosition().x, Broodwar->getScreenPosition().y };
  for (Unit u : Broodwar->getAllUnits()) {
    if (!u->isVisible() || !onScreen(u)) continue;
    frame["units"].push_back({
      {"id", u->getID()}, {"type", u->getType().getName()},
      {"owner", u->getPlayer()->getID()}, {"color", u->getPlayer()->getColor().getID()},
      {"x", u->getPosition().x}, {"y", u->getPosition().y},
      {"box", {u->getLeft(), u->getTop(), u->getRight(), u->getBottom()}},   // 충돌 사각형(맵 좌표)
      {"hp", u->getHitPoints()}, {"selected", u->isSelected()},
      {"flying", u->isFlying()}, {"lifted", u->isLifted()},
      {"constructing", u->isBeingConstructed()}, {"cloaked", u->isCloaked()}});
  }
  writeJson(f, frame);
  signalCaptureAndWait(f);   // 캡처 프로그램이 끝날 때까지 여기서 대기 → 게임 정지
}
```

#### [나] 화면 캡처 프로그램

- 직접 X 그래픽 인프라 화면 복제 방식(DXGI Desktop Duplication: DirectX Graphics Infrastructure의 화면 복제 기능)을 Python 라이브러리 `dxcam`으로 사용합니다.
  창이 가려졌을 때를 대비해 윈도우 그래픽 캡처(Windows.Graphics.Capture)를 예비로 둡니다.
- 게임 창의 클라이언트 영역(640×480)만 잘라서 **무손실 PNG**로 저장합니다. JPEG 같은 손실 압축은 팀 색상 픽셀을 망가뜨리므로 쓰지 않습니다.
- 마우스 커서는 화면 복제 방식에서 별도로 처리되므로 캡처에 들어가지 않습니다. 커서가 들어가는 경우를 대비해 데이터 생성 중에는 커서를 창 밖으로 옮겨 둡니다.
- 파일 이름: `{리플레이ID}_{프레임번호}.png`와 `{리플레이ID}_{프레임번호}.json`을 한 쌍으로 저장합니다.

**프레임 어긋남 보정 (반드시 처음에 실험):**
게임이 멈춘 순간 화면에 보이는 그림이 "기록한 상태와 같은 프레임"인지, "한 프레임 전"인지 확인해야 합니다.
움직이는 유닛 위치를 0/1/2프레임 차이별로 비교해 어긋남이 가장 작은 값을 정하고 설정값으로 고정합니다.
범용 분할 모델이 실제 픽셀에 맞춰 테두리를 다시 따기 때문에 1–2픽셀 어긋남은 자동으로 흡수됩니다.

#### [다] 마스크 생성 프로그램 (범용 분할 모델 사용)

- **모델:** 메타(Meta)의 범용 분할 모델 2.1 대형(`sam2.1-hiera-large`)을 기본으로 씁니다. 더 새로운 버전이 나와 있으면 같은 방식으로 교체합니다.
  사각형 힌트를 주면 그 안의 물체 테두리를 따 주는 기능("박스 프롬프트")을 씁니다.
- **실행 환경:** 게임을 돌리는 같은 윈도우 10/11 컴퓨터, RTX 3090, Python 3.11, PyTorch 2.x CUDA 판 (CUDA는 엔비디아 그래픽 카드 병렬 계산 플랫폼인 Compute Unified Device Architecture).
  범용 분할 모델 2의 선택형 CUDA 확장은 윈도우에서 빌드하지 않습니다(작은 구멍 메우기 후처리용이라 없어도 됨). 설치가 막히면 같은 컴퓨터의 WSL2(윈도우 안의 우분투)에서 이 단계만 돌립니다.
  게임 캡처가 끝난 뒤에 실행합니다(그래픽 카드를 함께 쓰므로).
- **처리 순서 (화면 1장마다):**
  1. 640×480 화면을 **2배 확대**(1280×960)합니다. 해병은 화면에서 가로세로 약 16–20픽셀밖에 안 돼서 원본 크기로는 분할 모델이 테두리를 잘 못 땁니다.
  2. 각 유닛의 충돌 사각형을 화면 좌표로 바꿉니다(맵 좌표 − 카메라 위치). 그리고 **종류별 여유 폭**만큼 넓힙니다.
     예: 건물은 위쪽으로 크게 넓히고, 전차는 사방으로 넓힙니다. 여유 폭 표는 종류마다 한 번 측정해 설정 파일로 둡니다.
  3. 넓힌 사각형들을 한꺼번에 분할 모델에 넣어 유닛별 마스크를 얻습니다.
  4. **그림자 제거:** 공중 유닛(레이스, 수송선 등)은 아래쪽에 그림자가 그려집니다. 그림자 위치에 "여기는 아님" 점(음성 점 프롬프트)을 함께 줍니다.
  5. **겹침 정리:** 두 마스크가 같은 픽셀을 차지하면, 게임이 위에 그리는 유닛에게 그 픽셀을 줍니다. 게임은 공중 → 지상, 같은 높이면 화면 y좌표가 큰(아래쪽) 것을 위에 그립니다.
     정리한 결과 원래 넓이의 20% 미만만 남은 유닛은 "가려짐"으로 표시하고 학습에서 제외합니다.
  6. **화면 하단 조작판 영역 제거:** 화면 아래의 조작판(미니맵·정보창·명령 버튼이 있는 영역)에 가려진 부분은 미리 만든 조작판 모양 마스크로 잘라냅니다.
  7. 마스크를 원래 크기(640×480)로 줄이고, 마스크에서 **최종 박스를 다시 계산**합니다.
- **품질 자동 검사 (불합격이면 그 객체 또는 그 화면을 버림):**
  - 마스크 넓이 ÷ 종류별 기준 넓이가 0.3–2.0 범위를 벗어남 → 분할 실패로 판단
  - 마스크가 유닛 중심점(게임이 알려준 위치)을 포함하지 않음 → 엉뚱한 물체를 딴 것
  - 분할 모델의 신뢰 점수가 0.7 미만
  - 한 화면에서 불합격 객체가 30%를 넘으면 그 화면 전체를 버림
- **사람 검수:** 무작위 1%의 화면에 마스크를 겹쳐 그린 이미지를 만듭니다. 이를 컴퓨터 비전 라벨링 도구(CVAT, Computer Vision Annotation Tool)에 올려 사람이 확인하고, 불량률이 5%를 넘으면 여유 폭 표나 검사 기준을 고칩니다.

```python
# 마스크 생성 핵심 (개념 코드)
import numpy as np, cv2, torch
from sam2.sam2_image_predictor import SAM2ImagePredictor

predictor = SAM2ImagePredictor.from_pretrained("facebook/sam2.1-hiera-large")

def make_masks(png_path, units, camera, margins, scale=2):
    img = imread_rgb(png_path)   # 윈도우 한글 경로에서도 동작하는 읽기 (datagen/common/imageio.py)
    big = cv2.resize(img, None, fx=scale, fy=scale, interpolation=cv2.INTER_CUBIC)
    boxes = []
    for u in units:
        l, t, r, b = u["box"]
        ml, mt, mr, mb = margins[u["type"]]                # 종류별 여유 폭
        boxes.append([(l - camera[0] - ml) * scale, (t - camera[1] - mt) * scale,
                      (r - camera[0] + mr) * scale, (b - camera[1] + mb) * scale])
    with torch.inference_mode(), torch.autocast("cuda", dtype=torch.bfloat16):
        predictor.set_image(big)
        masks, scores, _ = predictor.predict(box=np.array(boxes), multimask_output=False)
    masks = masks.reshape(len(units), *big.shape[:2])   # (유닛 수, 높이, 너비)
    masks = resolve_overlap(masks, units)                # 그리는 순서로 겹침 정리
    masks = [cv2.resize(m.astype(np.uint8), (640, 480), interpolation=cv2.INTER_NEAREST) for m in masks]
    return [apply_console_mask(m) for m in masks], scores
```

#### [라] 데이터셋 구성 프로그램

- **라벨 형식:** 객체 인식 모델(YOLO, You Only Look Once) 분할 학습 형식을 씁니다. 화면 1장당 텍스트 파일 1개, 객체 1개당 한 줄입니다.
  ```
  <클래스번호> x1 y1 x2 y2 x3 y3 ...     (다각형 꼭짓점, 0–1로 정규화한 좌표)
  ```
- 마스크 → 다각형 변환: `cv2.findContours`로 외곽선을 찾고, `cv2.approxPolyDP`(허용 오차 1픽셀)로 꼭짓점 수를 줄입니다.
  가려져서 마스크가 두 조각 이상으로 나뉘면 큰 조각만 쓰고, 작은 조각이 전체의 30% 이상이면 두 조각을 가는 선으로 이어 하나의 다각형으로 만듭니다.
- **원본 속성 보관:** 소유자, 색상, 체력, 선택 여부, 건설 중 여부는 학습 형식에 넣을 수 없습니다. 별도 JSON(공통 객체 문맥 데이터셋 형식, COCO: Common Objects in Context)으로 같이 저장해 소유자 판정기 학습과 평가에 씁니다.

### 1.6 평가 데이터를 만드는 방법

평가 데이터는 학습 데이터와 **절대 섞이면 안 됩니다.**
같은 경기의 연속된 화면은 거의 똑같기 때문에, 화면 단위로 무작위 분할하면 시험 점수가 실제보다 훨씬 높게 나옵니다.
그래서 아래 다섯 가지를 따로 만듭니다.

| 평가 세트 | 만드는 법 | 무엇을 확인하나 |
|---|---|---|
| ① 검증 세트 | 리플레이 단위로 10%를 떼어냄 (학습 중 조기 종료·하이퍼파라미터 선택용) | 학습이 잘 되고 있는지 |
| ② 시험 세트 | 리플레이 단위로 또 다른 10%. 학습이 끝날 때까지 한 번도 안 봄 | 최종 성능 |
| ③ 처음 보는 맵 세트 | 학습에 **한 번도 안 쓴 맵 3종**의 리플레이만으로 만듦 | 맵 배경(지형 타일)이 바뀌어도 되는지 |
| ④ 실제 대전 세트 | 리플레이가 아니라 **실제로 게임을 하면서**(사람 또는 내장 컴퓨터 상대) 같은 수집 모듈로 캡처. 아군 유닛 선택 원, 드래그 상자, 마우스 커서 등 리플레이와 다른 요소가 들어감 | 리플레이 화면과 실제 플레이 화면 차이에 강한지 |
| ⑤ 정밀 검수 세트 | ②·③·④에서 1,000장을 골라 **사람이 마스크를 직접 고침** (컴퓨터 비전 라벨링 도구 사용) | 자동 라벨 자체의 오차가 얼마인지, 모델의 진짜 성능 |

⑤번은 특히 중요합니다. 자동 라벨에도 오류가 있으므로, 자동 라벨과 사람이 고친 라벨을 비교하면 "자동 라벨의 정확도"를 숫자로 알 수 있습니다.
모델 점수가 이 값을 넘을 수는 없습니다.

**평가 지표:**
- 박스·마스크 각각 평균 정밀도 평균 (IoU 0.5 기준, IoU 0.5–0.95 평균)
- 클래스별 정밀도·재현율, 클래스 혼동 행렬 (예: 해병을 화염방사병으로 착각하는 비율)
- 크기별 재현율 (작은 유닛)
- 밀집 장면의 개수 오차 (해병 30기 뭉치에서 몇 기를 찾았나)
- 소유자 판정 정확도
- 추론 시간: 평균과 상위 95% 지점 지연

#### 학습 코드 (`perception/detect/train.py`)

```python
from ultralytics import YOLO

model = YOLO("yolo11s-seg.pt")          # 공통 객체 문맥 데이터셋으로 사전 학습된 소형 분할 모델
model.train(
    data="sc_terran.yaml",
    imgsz=640, epochs=150, batch=32, device=0,
    patience=30,                         # 검증 성능이 30회 연속 안 오르면 조기 종료
    # ---- 게임 화면에 맞춘 데이터 증강 설정 ----
    hsv_h=0.0, hsv_s=0.0,                # 색조·채도 변경 금지: 팀 색상이 소유자 정보이므로
    hsv_v=0.15,                          # 밝기만 약간 (전장의 안개로 어두워진 화면 대비)
    degrees=0.0, shear=0.0, perspective=0.0,  # 회전·기울임 금지: 게임 화면은 절대 회전하지 않음
    flipud=0.0,                          # 상하 반전 금지
    fliplr=0.0,                          # 좌우 반전도 처음엔 끔 (건물 그림은 반전된 모습이 게임에 없음)
    scale=0.1,                           # 크기 변화 ±10%만 (게임은 확대·축소가 없음)
    mosaic=1.0, close_mosaic=15,         # 4장 이어붙이기 증강, 마지막 15회는 끔
    copy_paste=0.3,                      # 마스크가 있어서 가능한 '객체 오려 붙이기' 증강 → 밀집 장면 대비
    project="runs/terran", name="s640",
)
```

학습 과정에서 실제로 일어나는 일:
PyTorch가 화면을 640×640으로 맞춘 뒤(위아래 여백 추가) 신경망에 넣습니다.
박스 위치 손실, 클래스 손실, 마스크 손실의 합을 줄이도록 가중치를 갱신하고, 매 회차가 끝날 때마다 검증 세트로 평균 정밀도 평균을 계산해 가장 좋은 가중치를 `best.pt`로 저장합니다.

**좌우 반전에 대한 메모:** 게임은 왼쪽을 보는 유닛을 오른쪽을 보는 그림을 반전시켜 그립니다. 그래서 유닛은 반전해도 자연스럽지만 건물은 아닙니다.
1차 학습은 반전 없이 하고, 유닛만 반전하는 맞춤 증강을 2차 실험으로 비교합니다.

#### 평가와 배포용 변환

```python
model = YOLO("runs/terran/s640/weights/best.pt")
for split in ["test", "unseen_maps", "live", "gold"]:      # 평가 세트 ②–⑤
    m = model.val(data=f"sc_terran_{split}.yaml", split="test", imgsz=640)
    print(split, "박스 mAP50:", m.box.map50, "마스크 mAP50:", m.seg.map50)

# 실행 컴퓨터(윈도우, RTX 3090)용으로 엔비디아 추론 최적화 엔진(TensorRT) 16비트 부동소수점 변환
model.export(format="engine", half=True, imgsz=640)
```

- 추론 최적화 엔진 파일은 실행할 컴퓨터의 그래픽 카드·드라이버에서 직접 변환해야 합니다. 그래서 변환은 윈도우 실행 컴퓨터에서 합니다.
- 대안으로 개방형 신경망 교환 형식(ONNX, Open Neural Network Exchange)으로 내보내 ONNX Runtime에서 실행할 수도 있습니다.

### 1.8 소유자 판정 (아군/적군/중립)

브루드워는 256색 팔레트 게임이고, 유닛 그림의 일부 픽셀(팔레트 8–15번)이 **플레이어 색상으로 바꿔 칠해집니다**(빨강, 파랑, 청록, 보라, 주황, 갈색, 흰색, 노랑 각 8단계).
그래서 별도 신경망 없이 다음처럼 판정할 수 있습니다.

1. 각 플레이어 색상의 8단계 RGB 값표를 게임 파일에서 한 번 뽑아 둡니다.
2. 객체 인식 모델이 낸 마스크 안의 픽셀 중 각 색상표와 정확히 일치하는 픽셀 수를 셉니다.
3. 가장 많은 색 = 소유자 색. 게임 시작 때 "색 → 아군/적군" 대응을 한 번 확정합니다.
4. 광물·가스는 클래스 자체로 중립입니다.

무손실 캡처라서 색이 정확히 일치합니다. 전장의 안개로 어두워진 화면은 어두운 색상표를 따로 둡니다.
평가 세트 ②–⑤에서 정확도를 재고, 99% 미만이면 작은 분류 신경망(합성곱 신경망)을 보조로 붙입니다.

**관심 영역**(화면에서 특정 정보가 항상 나오는 고정 사각형: 메인 화면, 미니맵, 자원 표시줄, 정보창, 명령 버튼 3×3)을 해상도별 설정 파일로 정의합니다.

## 3단계. 추적과 "현재 게임 상태" 조립 (3주)

1. **추적기:** 바이트트랙(ByteTrack) 방식의 다중 객체 추적기를 **맵 좌표계**에서 돌립니다. 카메라가 움직여도 같은 유닛이 같은 번호를 유지합니다.
2. **화면 밖 유닛:** 카메라 밖으로 나간 유닛은 미니맵 점과 맞춰 위치를 갱신합니다. 시간이 지날수록 "위치 불확실도"를 키웁니다.
3. **적 건물 기억:** 한 번 본 적 건물은 파괴를 확인할 때까지 기억합니다.
4. **"현재 게임 상태" 구조체:** 헤더(식별값, 버전, 순번, 캡처 시각, 게시 시각), 카메라, 자원, 유닛 목록, 미니맵 점, 시야, 선택 상태, 화면 상태, 명령 버튼 활성 여부로 구성합니다.
   - 이 구조체 정의는 **인터페이스 정의 파일 한 곳**에 두고, C++ 헤더와 Python numpy 구조체를 자동 생성해 두 언어가 항상 같은 배치를 쓰게 합니다.
5. **공유 메모리 게시:** 순번 잠금(seqlock: 쓰는 중에는 순번을 홀수로, 다 쓰면 짝수로 바꿔 읽는 쪽이 깨진 데이터를 걸러내는 방식) + 이중 버퍼로 게시합니다. 쓰는 쪽은 하나뿐이라 잠금이 필요 없습니다.
6. **평가:** 같은 리플레이를 재생하면서 이 상태와 게임 정보 인터페이스 라이브러리의 정답을 나란히 기록하는 **비교 도구**를 만듭니다. 여기서 나온 오분류율·누락률·위치 오차가 6단계 "인식 잡음 흉내 변환기"의 실측 값이 됩니다.
7. **전체 시간 목표:** 캡처 3밀리초 + 객체 인식 12밀리초 + 기타 인식·추적·게시 5밀리초 = 화면 1장 20밀리초 이하, 초당 30장.

## 4단계. 입력 제어 프로그램 (3–4주, 1단계와 병행 가능)

추상 행동(예: "해병 5기를 선택해 (1200, 800)으로 공격하며 이동")을 실제 키보드·마우스 입력으로 바꿔 게임에 보냅니다.
C++ 또는 Rust로 작성합니다.

| 구성 요소 | 하는 일 |
|---|---|
| 창 좌표 정규화 | 화면 배율(DPI, 인치당 점 수) 인식 모드를 켜고, 창의 실제 경계를 데스크톱 창 관리자 API(`DwmGetWindowAttribute`)로 구해 게임 좌표 → 모니터 좌표로 변환 |
| 변환기 | 행동 → 저수준 입력 순서. 대상이 화면 밖이면 먼저 미니맵 클릭이나 카메라 저장 위치(F2–F4)로 이동. 선택은 부대 지정 번호 → 드래그 → Shift+클릭 순으로 시도 |
| 일정 관리자 | 분당 유효 행동 수 상한 300, 입력 사이 최소 8밀리초, 키 누름 유지 10–20밀리초. 긴급한 교전 행동이 오면 진행 중인 생산 행동을 안전한 지점에서 끊음 |
| 입력 주입기 | 윈도우 `SendInput` 함수로 입력. 게임 창이 맨 앞이 아니면 즉시 중단, F12 비상 정지 키, 마우스 좌표를 게임 창 안으로 제한 |
| 결과 확인기 | 다음 "현재 게임 상태"로 효과 확인(선택 수 일치, 자원 감소, 생산 대기열 증가 등). 3프레임 안에 효과가 없으면 1회 재시도, 그래도 실패하면 두뇌에 실패 보고 |

**시험 방법:** 1단계 수집 모듈을 실제 대전 모드로 돌리면 게임 내부의 정답 상태를 "현재 게임 상태" 형식으로 내보낼 수 있습니다.
화면 인식이 완성되기 전에도 이 정답 상태를 입력으로 써서 입력 제어 프로그램을 시험할 수 있습니다.
- 시나리오 100개 성공률 98% 이상
- 입력 지연 상위 95% 지점 30밀리초 이하

**운영 조건:** `SendInput`은 맨 앞 창에만 전달되므로 전용 컴퓨터에서 게임을 맨 앞에 고정하고, 원격 접속이나 서비스가 아닌 로그인된 화면 세션에서 실행합니다.

## 5단계. 규칙 기반 두뇌로 통합 시험 (3주)

학습된 두뇌 없이 **사람이 짠 규칙**으로 세 프로그램을 연결해, 화면만 보고 게임을 끝까지 할 수 있는지 확인합니다.

- **규칙 두뇌:**
  - 고정 빌드 1종 (예: 테란 2병영 해병·의무관)
  - 일꾼 자동 채취
  - 규칙 기반 건물 배치기 (지을 수 있는 타일, 광물 줄 피하기). 이후 단계에서도 계속 씀
  - 병력이 일정 수 이상이면 공격 이동, 체력이 낮으면 후퇴
  - 사건 기반 카메라 이동 (공격받음, 생산 완료, 공격 목표)
  - 이상 상태 복구 (Esc, F2)
- **감독 프로그램:**
  - 공유 메모리를 소유하고, 200밀리초마다 각 프로그램의 생존 신호를 확인합니다. 1초간 응답이 없으면 그 프로그램을 재시작합니다.
  - 화면 인식이 500밀리초 넘게 멈추면 두뇌와 입력을 정지시킵니다.
- **비교 실험:** 같은 규칙 두뇌를 (가) 게임 내부 정답 상태 입력, (나) 화면 인식 입력으로 각각 돌립니다. 승률 차이가 "인식 때문에 잃는 성능"의 첫 측정값입니다.
- **완료 기준:** 화면만으로 내장 컴퓨터(테란) 상대 승률 80% 이상, 100판 동안 화면 상태 꼬임으로 멈추는 일 0건.

## 6단계. 리플레이 행동 복제 학습 (8주, 리눅스)

**행동 복제(Behavior Cloning)**: 사람 경기 기록(리플레이)에서 "이 상황에서 사람이 이 행동을 했다"는 쌍을 뽑아, 같은 상황에서 같은 행동을 하도록 신경망을 지도학습하는 방법입니다.

1. **상태 추출:** 오픈소스 브루드워 재구현 엔진(OpenBW)을 리눅스에서 화면 없이 실행해 리플레이를 빠르게 재생하고, 프레임별 정답 상태를 저장합니다.
   이 엔진은 원본 게임 동작을 그대로 재현하면서 훨씬 빠르고 리눅스에서 돕니다.
2. **명령 → 추상 행동 변환:** 리플레이에 기록된 명령(선택, 부대 지정, 우클릭, 건설, 생산, 연구 등)을 4단계의 추상 행동으로 바꿉니다.
   - 200밀리초 안의 반복 클릭은 합칩니다.
   - 리플레이에는 카메라 이동이 기록되지 않으므로, 대상이 화면 밖이면 카메라 이동 행동을 끼워 넣습니다.
3. **인식 잡음 흉내 변환기 (원본의 "화면 등가 상태"):** 정답 상태를 "화면 인식 프로그램이 실제로 만들어 낼 법한 상태"로 바꿉니다.
   - 적은 보이는 곳에만 둡니다.
   - 가상 카메라 밖의 유닛은 미니맵 점 수준으로 정보를 줄입니다.
   - 체력은 선택됐거나 맞는 중일 때만 줍니다.
   - 3단계 비교 도구로 잰 오분류율·누락률·위치 오차를 그대로 주입합니다.
   - 이렇게 해야 화면을 보지 않고 학습한 두뇌가 실제 화면 입력에서도 작동합니다.
4. **신경망 (약 1천만–3천만 개 매개변수):**
   - 유닛 목록을 처리하는 트랜스포머 (4층, 폭 384)
   - 지도 격자(128×128)를 처리하는 잔차 합성곱 신경망
   - 전역 정보(자원, 시간 등)를 처리하는 다층 퍼셉트론
   - 시간 흐름을 기억하는 게이트 순환 유닛(GRU, Gated Recurrent Unit) 1024
   - 출력: 행동 종류 → 인자 → 좌표(거친 8×8 + 세밀 16×16) 또는 대상 유닛 순서로 고르는 계층형 출력부, 승률 예측부
   - "지금 할 수 없는 행동"(자원 부족, 회색 버튼)은 출력에서 가립니다.
5. **학습:** 행동 종류·인자·좌표의 교차 엔트로피 손실에 승패·적 조합 예측 보조 손실을 더합니다. PyTorch, 리눅스 RTX 3090 또는 DGX Spark를 씁니다.
6. **완료 기준:** 행동 종류 1순위 정확도 60% 이상, 오픈소스 재구현 엔진 안에서 내장 컴퓨터 상대 승률 70% 이상.
7. **실제 화면 배포:** 모델을 추론 최적화 엔진으로 변환해 5단계 규칙 두뇌 자리에 넣습니다. 건물 배치와 카메라는 계속 규칙을 씁니다(리플레이에 카메라 기록이 없어서 배울 수 없음).

## 7단계. 강화학습 미세조정 (10주, 리눅스)

**강화학습(Reinforcement Learning)**: 정답 없이 실제로 게임을 해 보고, 이기면 보상을 받는 방향으로 신경망을 고쳐 가는 방법입니다.

1. **환경:** 오픈소스 재구현 엔진을 화면 없이 수십 개 동시에 돌립니다. 관측은 반드시 인식 잡음 흉내 변환기를 거칩니다.
2. **알고리즘:** 근접 정책 최적화(PPO, Proximal Policy Optimization)를 씁니다. 정책을 한 번에 너무 크게 바꾸지 않도록 변화 폭을 제한하는 강화학습 알고리즘입니다. 대안은 중요도 보정 비정책 학습(V-trace)입니다.
3. **행동 복제 정책에서 너무 멀어지지 않게:** 두 정책의 확률 분포 차이(쿨백-라이블러 발산)에 벌점을 줍니다. 처음부터 학습하면 비용이 너무 크기 때문에 행동 복제 결과에서 출발하는 것이 필수입니다.
4. **상대 풀:** 과거 자신의 저장본, 오픈소스 봇, 내장 컴퓨터를 섞고, 실력 점수(엘로 평점)로 상대를 고릅니다.
5. **오프닝 선택:** 상대별 승패 기록으로 고르는 다중 슬롯머신 알고리즘(신뢰 상한 방식)을 씁니다.
6. **(선택) 오프라인 강화학습:** 새 게임 없이 리플레이 데이터의 승패만으로 행동 복제를 보정하는 방법(내재 Q-학습 IQL, 가치 가중 행동 복제 AWAC 계열)을 행동 복제와 온라인 강화학습 사이에 넣을 수 있습니다.
7. **완료 기준:** 내장 컴퓨터 상대 95% 이상, 오픈소스 중위권 봇 상대 50% 이상.

## 8단계. 시뮬레이션과 실제 화면 차이 보정 (6주)

1. 실제 화면 루프(세 프로그램 + 게임)로 수백 판을 둡니다.
2. 3단계 비교 도구로 인식 오차를 다시 재서 인식 잡음 흉내 변환기를 갱신하고, 두뇌를 소량 다시 학습합니다.
3. 최종 지표: 같은 두뇌를 "게임 내부 정답 입력"과 "화면 입력"으로 돌렸을 때의 승률 차이를 10%포인트 이하로 줄입니다.
4. 이후 확장:
   - 저그·프로토스: 1단계 파이프라인을 다시 돌려 데이터만 추가
   - 리마스터 버전: 해상도·그림이 다르므로 객체 인식 모델을 추가 학습

## 9. 운영 범위와 약관

- 블리자드 최종 사용자 사용권 계약은 봇과 허가받지 않은 게임 변경 프로그램을 금지합니다. 화면 캡처 + 입력 방식도 예외가 아닙니다.
- 따라서 **오프라인 1.16.1, 내장 컴퓨터 상대 싱글 플레이, 근거리 통신망(LAN) 대전, 봇 대회 관리자 환경에서만** 실행하고 평가합니다. 온라인 공식 대전(래더)에서는 절대 사용하지 않습니다.
